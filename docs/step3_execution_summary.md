# 3단계 실행 요약: LLM-as-Judge 및 HyDE 기법 구현

## 구현 완료

### 3.1 LLM-as-Judge 구현 (`retriever/llm_judge.py`)

- **`LLMJudge` 클래스**: 질의와 후보 조항을 비교하여 위반 가능성 판단
- **`judge_single()`**: 단일 후보에 대한 위반 가능성 평가
- **`judge_batch()`**: 여러 후보를 배치로 평가하고 순위화
- **`compare_candidates()`**: 여러 후보를 한 번에 비교하여 상대적 순위 결정

### 3.2 HyDE 구현 (`retriever/hyde_retriever.py`)

- **`HyDERetriever` 클래스**: 가상 문서 생성 기반 검색
- **`generate_hypothetical_document()`**: 질의에 대한 가상 문서 생성
- **`search_with_hypothetical_doc()`**: HyDE 기법을 사용한 검색
- **`enhance_with_hyde()`**: 기존 후보 검색 결과를 HyDE로 보강

### 3.3 통합 리트리버 (`retriever/enhanced_retriever.py`)

- **`EnhancedRetriever` 클래스**: 모든 기법 통합
- **프로세스**:
  1. 하이브리드 검색으로 초기 후보 선별
  2. HyDE로 가상 문서 생성 및 추가 후보 확보
  3. LLM-as-Judge로 최종 후보들 평가 및 순위화

### 3.4 테스트 (`retriever/test_enhanced_retriever.py`)

- 5개 테스트 케이스로 성능 검증
- 통합 점수 및 LLM 위반 가능성 점수 계산
- 상세 결과 및 근거 제공

## 테스트 결과

### 초기 테스트 결과

- 정확도: 2/5 (40.0%)
- 문제점:
  - LLM이 모든 경우에 비슷한 근거 제공
  - LLM 위반 가능성이 0.850으로 고정되는 현상
  - 조항별 특성을 제대로 구분하지 못함
  - 하이브리드 검색에서 잘못된 조항이 상위에 랭킹

### 개선 사항

#### 1. LLM 프롬프트 개선

- 조항별 특성을 명시하고 더 구체적인 지시사항 제공
- 법률 조항 내용 전체 제공으로 더 정확한 판단 가능
- 여러 후보를 한 번에 비교하여 상대적 순위 결정

#### 2. 하이브리드 검색 개선 (옵션 A)

- **조항별 키워드/패턴 통합**: `judge_clause.py`의 `ARTICLE_PATTERNS` 활용
- **키워드 매칭 강화**: 조항별 특정 키워드 매칭 시 가중치 부여
- **패턴 매칭 추가**: 정규식 패턴 매칭으로 더 정확한 조항 식별
- **가중치 조정**: 키워드 점수 가중치 30% → 40%로 증가
- **검색 범위 확대**: 의미적 검색 후보 수 20개 → 30개로 증가

#### 3. 최종 테스트 결과

- **정확도: 4/5 (80.0%)** ✅
- 성공 케이스:
  - 테스트 1: 제7조 (면책 조항) ✓
  - 테스트 2: 제9조 (해지 권한 제한) ✓

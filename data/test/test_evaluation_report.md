## 📊 성능 지표 상세 분석

### 2.1 혼동 행렬 (Confusion Matrix)

성능 평가의 기초가 되는 혼동 행렬은 다음과 같이 구성됩니다:

| 구분 | 실제: 준수 | 실제: 위반 |
|------|------------|------------|
| **예측: 준수** | TN = 72 | FN = 39 |
| **예측: 위반** | FP = 8 | TP = 110 |

**용어 설명:**

- **TN (True Negative)**: 준수 문장을 준수로 정확히 판정
  - 72개 문장이 정상적으로 통과 (임계값 0.3 미만)

- **FP (False Positive)**: 준수 문장을 위반으로 오판 (오탐지)
  - 8개 문장이 잘못 위반으로 판정 (임계값 0.3 이상)
  - 문제: 정상 약관을 불공정으로 잘못 판단

- **TP (True Positive)**: 위반 문장을 위반으로 정확히 탐지
  - 110개 위반을 정확히 탐지하고 정확한 조항으로 분류

- **FN (False Negative)**: 위반 문장을 탐지하지 못함 (미탐지)
  - 39개 위반을 놓침 (임계값 0.3 미만)
  - **가장 심각한 문제**: 실제 불공정 약관을 발견하지 못함

### 2.2 핵심 성능 지표

#### 1) Accuracy (정확도)

**정의**: 전체 예측 중 정답의 비율

```
Accuracy = (TP + TN) / (TP + TN + FP + FN)
         = (110 + 72) / (110 + 72 + 8 + 39)
         = 182 / 240
         = 0.7583 (75.8%)
```

**해석**: 전체 240개 케이스 중 182개를 정확히 판정했습니다.

#### 2) Precision (정밀도)

**정의**: 위반으로 예측한 것 중 실제로 위반인 비율

```
Precision = TP / (TP + FP)
          = 110 / (110 + 8)
          = 110 / 118
          = 0.9322 (93.2%)
```

**해석**: 시스템이 '위반'이라고 판정한 118개 중 110개(93.2%)가 실제로 위반이었습니다.

✅ **우수**: 오탐지가 적어 신뢰도가 높습니다.

#### 3) Recall (재현율 / 민감도)

**정의**: 실제 위반 중 시스템이 탐지한 비율

```
Recall = TP / (TP + FN)
       = 110 / (110 + 39)
       = 110 / 149
       = 0.7383 (73.8%)
```

**해석**: 실제 위반 149개 중 110개(73.8%)를 탐지했고, 39개(26.2%)를 놓쳤습니다.

🔴 **부족**: 39개 위반을 놓쳐 개선이 필요합니다.

#### 4) F1 Score (조화 평균)

**정의**: Precision과 Recall의 조화 평균

Precision과 Recall은 서로 trade-off 관계에 있습니다:
- Precision을 높이면 → 확실한 것만 탐지 → Recall 감소
- Recall을 높이면 → 많이 탐지 → Precision 감소 (오탐지 증가)

F1 Score는 이 두 지표의 균형을 평가합니다.

```
F1 Score = 2 × (Precision × Recall) / (Precision + Recall)
         = 2 × (0.9322 × 0.7383) / (0.9322 + 0.7383)
         = 2 × 0.6882 / 1.6705
         = 1.3764 / 1.6705
         = 0.8240
```

**F1 Score 해석:**

- ✅ **우수** (0.824): 균형 잡힌 성능을 보입니다.

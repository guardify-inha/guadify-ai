# AI.csv 데이터 테스트 리포트

## 📋 테스트 개요

이 리포트는 **약관 규제에 관한 법률**에 따른 불공정 약관 판단 시스템의 성능을 평가한 결과입니다.

### 테스트 설정

- **데이터 소스**: `ai.csv` (실제 불공정 약관 사례 데이터)
- **전체 데이터**: 1,004개 행
- **유효한 데이터**: 950개
- **샘플링**: 100개 (불공정 원문 100개 + 공정 수정본 100개 = 총 200개 테스트)
- **판단 시스템**: GraphRAGJudge (v8.1 - Fixed)
- **LLM 제외 모드**: Phase 6 (의미 반전 검증), Phase 8 (설명 생성), 수정 제안 기능 제외
- **판단 임계값**: 0.65

### 테스트 목적

1. **불공정 약관 원문**을 입력했을 때 → 위반으로 정확히 판단하는지 확인 (True Negative)
2. **공정 수정본**을 입력했을 때 → 정상으로 정확히 판단하는지 확인 (True Positive)

## 🔍 판단 프로세스 상세 설명

각 약관은 **8단계 Phase**를 거쳐 최종 판단됩니다:

### Phase 0: 패턴 기반 위험도 분석

**목적**: 미리 정의된 불공정 약관 패턴과 키워드를 매칭하여 초기 위험도를 평가합니다.

**작동 방식**:

- `patterns_by_article_v2.json` 파일에서 각 조항별 위험 키워드 패턴을 로드
- 입력 텍스트에서 해당 키워드가 발견되면 위험도 점수 부여
- 위험도 레벨: `none` → `low` → `medium` → `high` → `critical`

**예시**:

```
✅ 매칭 키워드: 2개
   위험도: critical
   패턴 점수: 0.300
```

**의미**: "피해배상", "책임지지 않는다" 등의 키워드가 발견되어 높은 위험도로 평가됨

---

### Phase 1: 불공정 사례 유사도 검색

**목적**: 벡터 임베딩을 사용하여 과거 불공정 약관 사례와의 유사도를 검색합니다.

**작동 방식**:

- 입력 텍스트를 벡터로 변환 (BAAI/bge-m3 모델 사용)
- Neo4j 데이터베이스에서 유사한 불공정 사례를 벡터 검색
- 상위 10개 유사 사례를 찾아 유사도 점수 계산

**예시**:

```
✅ 10개 유사 사례 발견
  🎯 선택된 조항: 제11조
     유사도: 0.999
     우선순위: 1 (6조=1, 나머지=높음)
     종합 점수: 0.999
```

**의미**: 데이터베이스에 저장된 과거 불공정 사례 중 매우 유사한 사례를 찾아 해당 조항(제11조)을 후보로 선정

---

### Phase 2: Prototypical Networks 기반 불공정도 계산

**목적**: 머신러닝 기법을 사용하여 불공정/공정 prototype과의 거리를 계산합니다.

**작동 방식**:

1. **Unfair Prototype**: 모든 불공정 약관 사례의 평균 임베딩 벡터
2. **Fair Prototype**: 모든 공정 약관 사례의 평균 임베딩 벡터
3. 입력 텍스트의 임베딩과 두 prototype 간의 거리 계산
4. 거리 기반으로 불공정 확률 계산 (Softmax with temperature)

**수식**:

```
P(unfair) = exp(-d_unfair / τ) / (exp(-d_unfair / τ) + exp(-d_fair / τ))
```

- `d_unfair`: Unfair prototype과의 거리
- `d_fair`: Fair prototype과의 거리
- `τ`: 온도 파라미터 (기본값: 0.5)

**예시**:

```
✅ 방법론: prototypical_networks_multi_prototype
✅ Unfair prototype 거리: 0.009
✅ Fair prototype 거리: 1.843
✅ 상대적 불공정도 (P(unfair)): 0.975
   온도 파라미터 τ: 0.5
   해석: 불공정 prototype에 매우 가깝습니다 (거리비: 0.01)
```

**의미**:

- Unfair prototype과 매우 가까움 (거리 0.009) → 불공정일 가능성 높음
- Fair prototype과 멀리 떨어져 있음 (거리 1.843) → 공정일 가능성 낮음
- 최종 확률: 97.5% 불공정

---

### Phase 3: 법률 구조 분석

**목적**: 약관 규제에 관한 법률의 구체적인 조항을 분석하여 위반 여부를 확인합니다.

**작동 방식**:

- Phase 1에서 찾은 유사 사례의 조항 정보 활용
- 각 조항별 위반 유형과 심각도 분석
- 조항별 우선순위 적용 (예: 제6조가 가장 높은 우선순위)

**예시**:

```
✅ 위반 조항: 제11조
   상세: ...
```

**의미**: 해당 약관이 약관 규제에 관한 법률 제11조를 위반하는 것으로 판단됨

---

### Phase 4: 종합 점수 계산

**목적**: 앞선 3단계의 결과를 가중 평균하여 최종 점수를 계산합니다.

**점수 구성 요소**:

1. **위반사례 유사도** (20% 가중치): Phase 1의 벡터 검색 결과
2. **Prototypical 불공정도** (60% 가중치): Phase 2의 prototype 거리 기반 확률
3. **JSON 패턴** (20% 가중치): Phase 0의 키워드 매칭 점수

**수식**:

```
최종 점수 = (유사도 × 0.2) + (불공정도 × 0.6) + (패턴점수 × 0.2)
```

**예시**:

```
  점수 구성:
    - 위반사례 유사도 (20%): 0.999 → 0.200
    - Prototypical 불공정도 (60%): 0.975 → 0.585
    - JSON 패턴 (20%): 0.300 → 0.060
  최종 수식 점수: 0.845
```

**의미**:

- 세 가지 요소를 종합하여 84.5%의 위반 확률로 계산됨
- Prototypical Networks가 가장 큰 영향력 (60%)을 가짐

---

### Phase 5: LLM 의미 반전 검증

**목적**: LLM을 사용하여 텍스트의 실제 의미가 반전되었는지 검증합니다.

**작동 방식** (이 테스트에서는 스킵됨):

- LLM에게 텍스트의 실제 의미를 분석하도록 요청
- 예: "책임지지 않는다"라는 표현이 실제로는 "책임진다"를 의미하는지 확인
- 의미 반전이 감지되면 점수 조정

**예시**:

```
📍 Phase 5: LLM 의미 반전 검증
----------------------------------------------------------------------
  ⏭️  LLM 의미 반전 검증 스킵
  ✅ 수식 점수 그대로 사용: 0.845
```

**의미**: 이 테스트는 LLM을 사용하지 않는 모드이므로 Phase 4의 점수를 그대로 사용

---

### Phase 6: 최종 판단 및 표현

**목적**: 계산된 점수를 기반으로 최종 판단을 내립니다.

**판단 기준**:

- **임계값**: 0.65
- 점수 ≥ 0.65 → ⚠️ **위반** (violation=True)
- 점수 < 0.65 → ✅ **정상** (violation=False)

**심각도 분류**:

- `critical`: 점수 ≥ 0.85
- `high`: 0.75 ≤ 점수 < 0.85
- `medium`: 0.65 ≤ 점수 < 0.75
- `low`: 0.50 ≤ 점수 < 0.65
- `none`: 점수 < 0.50

**예시**:

```
📍 Phase 6: 최종 판단 및 표현
----------------------------------------------------------------------
  최종 점수: 0.845
  판단: ⚠️ 위반
  심각도: medium
  표현: 위반으로 강하게 추정됩니다
```

**의미**: 84.5%의 점수로 위반으로 판단되며, medium 심각도로 분류됨

---

### Phase 7: 설명 생성

**목적**: 판단 근거를 설명하는 텍스트를 생성합니다.

**작동 방식** (이 테스트에서는 스킵됨):

- 각 Phase의 결과를 종합하여 사용자 친화적인 설명 생성
- 위반 조항, 유사 사례, 패턴 매칭 등을 포함한 상세 설명

**예시**:

```
📍 Phase 7: 설명 생성
----------------------------------------------------------------------
✅ 설명 완료
```

## 📈 시스템 아키텍처

### 사용 기술 스택

1. **Neo4j**: 그래프 데이터베이스 (불공정 사례 저장 및 검색)
2. **BAAI/bge-m3**: 벡터 임베딩 모델 (텍스트 유사도 계산)
3. **Prototypical Networks**: 머신러닝 기법 (불공정/공정 분류)
4. **GraphRAG**: 하이브리드 검색 (벡터 + 그래프)

### 데이터 흐름

```
입력 텍스트
    ↓
Phase 0: 패턴 매칭 (키워드 기반)
    ↓
Phase 1: 벡터 검색 (유사 사례 찾기)
    ↓
Phase 2: Prototypical Networks (불공정도 계산)
    ↓
Phase 3: 법률 조항 분석
    ↓
Phase 4: 종합 점수 계산 (가중 평균)
    ↓
Phase 5: LLM 검증 (선택적)
    ↓
Phase 6: 최종 판단
    ↓
Phase 7: 설명 생성 (선택적)
    ↓
최종 결과
```

## 🔬 테스트 케이스 예시

### 예시 1: 불공정 약관 (위반 판단)

**입력**:

```
회사는 어떠한 피해배상도 하지 않는다.
```

**판단 과정**:

1. **Phase 0**: "피해배상", "하지 않는다" 키워드 매칭 → 위험도: critical
2. **Phase 1**: 유사 사례 발견 → 제11조, 유사도: 0.999
3. **Phase 2**: Unfair prototype 거리 0.009 → 불공정도: 97.5%
4. **Phase 4**: 종합 점수 0.845
5. **Phase 6**: 점수 0.845 ≥ 0.65 → ⚠️ **위반** 판단

**결과**: ✅ 정확히 위반으로 판단됨

---

### 예시 2: 공정 약관 (정상 판단)

**입력**:

```
회사는 회사의 귀책사유로 인하여 회원에게 손해가 발생한 경우 관련 법령에 따라 배상 책임을 집니다.
```

**판단 과정**:

1. **Phase 0**: 위험 키워드 없음 → 위험도: none
2. **Phase 1**: 유사 사례 없음 → 전체 데이터베이스 prototype 사용
3. **Phase 2**: Fair prototype 거리 0.175 → 불공정도: 2.5%
4. **Phase 4**: 종합 점수 0.044
5. **Phase 6**: 점수 0.044 < 0.65 → ✅ **정상** 판단

**결과**: ✅ 정확히 정상으로 판단됨

## 💡 개선 가능 영역

### 1. LLM 통합 (선택적)

현재는 LLM을 사용하지 않지만, 필요시 다음 기능 추가 가능:

- **의미 반전 검증**: Phase 5에서 텍스트의 실제 의미 확인
- **설명 생성**: Phase 7에서 사용자 친화적인 설명 생성
- **수정 제안**: 불공정 약관의 개선안 제시

### 2. 임계값 조정

현재 임계값 0.65는 이 테스트에서 완벽하게 작동하지만, 실제 운영 환경에서는:

- 더 많은 테스트 데이터로 검증 필요
- 조항별로 다른 임계값 적용 고려
- 심각도별 임계값 차등화

### 3. 조항별 세부 분석

현재는 전체적인 위반 여부만 판단하지만, 향후:

- 조항별 위반 유형 분류
- 조항별 심각도 평가
- 조항별 수정 가이드라인 제공
